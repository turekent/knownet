## 一、任务 ID 与状态机

每一条片子/交付物都有固定 ID：`EP01`…`EP99`。

```
待办 → 进行中 → 待Hermes核 → 已放行 → 已交付
                   ↘ 已作废（只有用户或 Hermes 能判）
```

| 谁能改 | 允许改成 |
|---|---|
| **Rio / dsh** | 进行中 · 待Hermes核 |
| **Hermes** | 已放行 · 已交付 · 已作废 |
| **用户** | 任何状态（一句话即可，我改） |

**消息头必须带**：`[EP05 · 待Hermes核]`
→ 收件人一眼知道：在说哪一篇、卡在哪一环。

---

## 二、一条消息只谈一个任务，≤600 字

- **超了就拆**：一个任务一条消息。
- **长材料走文件**（上传口 + sha256），**不要塞进消息正文**。
- **消息只写**：结论 / 要对方做什么 / 卡在哪。背景放文件里。

---

## 三、回执三段式（"已交"不算回执）

```
收到 ✓
我做了什么 ✓   ← 必须附可验证句柄：文件名 + 字节数 + sha256 前16位 + 路径
卡在哪 ✗       ← 没有就写"无"
```

**反面教材**：「已交」「已完成」「都弄好了」—— 一律视为**没交** ✗。
**正面**：`kb5_shot_table_v2.json · 36,988B · sha 818402337531b1c8… · /uploads/…`

## 四、超时规则

| 情形 | 动作 |
|---|---|
| Rio/dsh 交件后 **2 小时** 无 Hermes 回执 | **主动催**：`[EP05] 2h 未核，请确认` |
| Hermes 被催后 **4 小时** 仍未核 | **升级到用户**，不要干等 |
| 任务 **6 小时** 无任何状态变化 | **在状态板上标"疑似卡住"**，并说明卡在哪 |

> 目的：不让任何一方"以为对方在做"。

## 八、v1.1 修正（2026-10-20 · 用户拍板）

**主链路只两方：Hermes ⇄ Rio。dsh 不进日常流水。**

| 场景 | 走谁 |
|---|---|
| 剧本 / 转写 / 镜头表 / 生成 / 验收 / 上线 | **Hermes ⇄ Rio 两方** ✓ |
| 交付包外部审查、代码审计、许可证核查 | **需要时单独叫 dsh 一次** ✓ 审完即走 |
| 日常任务状态 | 状态板 ✓ 不需要第三方确认 |

**理由（用户原话）**：「一个事情经过三个模型太麻烦了，效率不高」✗

**执行**：
1. 日常消息**不用**抄送 dsh ✗
2. dsh 只在**一个具体交付物需要独立复核**时被调用 ✓ 且**不阻塞主链路** ✓（主链路照常跑 ✓）
3. 任何任务**不得以"等 dsh 确认"为由停住** ✗

## 九、文字铁律（2026-10-21 起，永久生效）

> 起因：EP05/EP06 连续出现「挽上/完善」「得很完整了」「考的边界」「Python 入门完」等截字错字，
> 全部是**文字块固定宽度 + 溢出裁剪**导致，且**检查岗只查字幕、不查大字/字卡**。
> 以下六条，任何一篇、任何一版、任何人，不得例外。

### 9.1 唯一文本源
- **屏幕上的所有文字，只能来自「用户定稿」或「校订版 segs」** ✓
- **`segs.json`（ASR 原始输出）一律作废** ✗ 不得直接用于出片
- **AI 不得生成、改写、概括任何屏幕文字** ✗
- 字卡上没有对应原话 → **删掉，或从原话里摘** ✓

### 9.2 校订稿的归属
- **校订版由 Hermes 出** ✓（`*_segs_corrected.json`）
- **Rio / dsh 发现校订稿还有错 → 报 Hermes** ✓ **不许自己改** ✗
- 校订稿一旦发布，**旧版作废** ✗ 不得混用

### 9.3 排版引擎
- **文字块宽度必须自适应内容**（auto-size）✓
- **禁止 `overflow: hidden` / clip 裁掉文字** ✗
- 放不下时：**换行 → 缩字号 → 改构图** ✓ **不许截** ✗
- **文字块左右各留 ≥40px 画布安全边** ✓

### 9.4 bbox 校验（渲染后强制）
每块文字渲染后必须校验三项，任一不满足 → **报错，不许出片** ✗：
1. 文字实际宽度 ≤ 容器宽度
2. 容器 bbox 完整在画布内（左右 ≥40px）
3. 文字块 bbox 与主体/圆窗 bbox **不相交**

### 9.5 检查岗职责（渲染岗自测不算数）
- **检查范围 = 全画面所有文字** ✓：字幕 + 大字 + 字卡 + UI 标签 + 图表标注
- 逐块输出：`ID ｜ 内容 ｜ 实测宽 ｜ 容器宽 ｜ 溢出? ｜ 出画?`
- **任一溢出/出画/不一致 → 直接 FAIL** ✓
- **禁止「备注（不升 FAIL）」** ✗ —— 文字类问题一律升 FAIL
- **不许抽样** ✗ 每帧每块都要过

### 9.6 交件门槛
**以下三份齐全才算交件** ✓：
1. 主片 + 3 帧 + sha256 前16 + 字节数
2. `TEXT_CHECK.md`（检查岗出，逐帧逐块）
3. `SELFCHECK.md`（白块 / 重叠 / 圆窗）

**缺任何一份 = 未交** ✗

## 十、圆框不是必须的（2026-10-21 · 用户提出）

> 用户原话：「当与圆框的背景和整个画面的背景同色的时候，就没必要弄一个圆框了，这样显得很怪」

**10.1 圆框的作用**
圆框本质是「窗」——用来**把人物和背景区分开**。背景已经是纯色/同色时，这个窗失去意义，
只剩一圈突兀的边缘。

**10.2 判定规则**
- **背景有图案 / 渐变 / 场景** → 保留圆框 ✓
- **背景是纯色，或人物周围 200px 内颜色方差低于阈值** → **去掉圆框** ✓ 人物直接坐在背景上

**肉眼版判断**：退到 3 米外看——
- 能看到「一个圈」→ **怪** ✗ 去掉
- 只看到人 → **对** ✓

**10.3 去掉圆框 ≠ 去掉抠像**
alpha 仍然要有，人物外面必须透明；只是**不画圆形边界**，不需要一圈留白。
手/肩膀可以出画，更自然。

**10.4 边缘对比太强时怎么办**
暗底 + 浅衣这类强对比，可以加 **1–2px 柔和阴影**（`0 0 24px rgba(0,0,0,0.35)`）或干脆不加。
**不许**加白边 ✗ **不许**加描边 ✗
