# VidMuse + agent-motion 学习笔记（2026-10-24 实测）

## 0 一句话结论

**这两样不是"一键成片"，是"把口播拆成动画片段"的生产线。**
agent-motion = 渲染引擎（Three.js → 浏览器逐帧截帧 → H.264）
VidMuse 手册 = 生产纪律（怎么拆镜头、怎么审、怎么不烧钱）

**关键认知：它们产出的是"按句/按段的动画片段"，不是整片。**
整片 = 真人层 + 动画片段层 + 字幕层，用 ffmpeg 合成。

## 2 VidMuse 手册：11 道关（59 页，只记有用的）

### 最重要的三条

**① 不是每句话都做画面**
每个候选段只给**一个主要任务**：演示操作 / 解释原因 / 抽象落地 / 对比差异 / 看见规模 / 制造感受 / 连接上下文。
**以下保留真人**：个人态度、真实经历、"这是我的判断"、情绪落点、行动邀请。
> 不要为了显得制作量大，给每句话塞画面。

**② 抽象话必须变成"看得见的变化"**
公式：口播意思 → 12 岁版本 → 观众必须看见的变化 → 谁/什么 → 做了什么 → 状态怎么变 → 得到什么
四要素：**主体、动作、变化、结果**
反例："发光的 AI 标志旁边写'效率低'" = 坏画面
正例："人把任务交给实习生，实习生每步回来举手；人想走又被拉回；钟在转，任务只前进一点"

**③ 切镜头按"意思变化"，不按固定秒数**
出现这些才换节拍：新动作 / 主体变 / 因转果 / "但是、所以、真正、不是…而是" / 新数字新步骤 / 结论落地 / 情绪变化。
**填充词、同义重复、半秒看不清的新信息 → 不单独做镜头。**

### 两版故事板（这条最容易做错）

| 给人审的 | 给机器拍的 |
|---|---|
| 可以写满：分格/时间/箭头/编号/动作说明/原话 | 必须清掉：分格线/外框/时间码/箭头/底部说明/任何多余文字 |
| 任务是**让人快速发现问题** | 任务是**只给模型看画面** |

> **给人看的图可以写满注释；给机器拍视频的图要干净。**

### 花钱前必须停一次

不能从 SRT 一路无人审到付费生成。每段检查 10 条（能否认出主体/看懂动作/看见变化/为何只对这句/去掉关键词还成立吗/关键动作避开底部字幕区/镜头数由内容定/有接力点/无多余中文/预算可接受）。

### 成本

```
18 段 ≈ 170 秒动画 → 1020 积分
20 段 ≈ 174 秒动画 → 1044 积分
```
**故事板阶段发现错误 = 0 成本；生成后发现 = 重做整段。**

## 3 两个坑（手册 + 仓库都写了）

1 **许可证**：VidMuse 会员手册说"MIT"是过期说法；以仓库 `LICENSE` / `COMMERCIAL-LICENSE.md` 为准。RVM 权重是 GPL-3.0。
2 **审核图直接拿去生成** = 失败 8。分格线、箭头会被模型拍进成片。

## 4 对我们 EP06 的用法（直接可执行）

```
1 SRT 定稿（已有：69 句）
2 逐句判"要不要画面"，只要一个主要任务（不要每句都做）
3 要画面的句子 → 写"主体/动作/变化/结果"四要素
4 出一版干净参考图（无文字无边框）
5 渲静帧 → 人审（静音看动作 / 对原话看 / 看是否重复 / 看文字风险 / 看手机屏）
6 审过 → 渲序列 → 合成
7 真人层 + 动画层 + 字幕层 ffmpeg 合成
```

**现实约束**：VidMuse 平台要付费积分；我们**先用 agent-motion 本地渲**（零生成成本），只在本地做不出来的镜头才考虑外部模型。
