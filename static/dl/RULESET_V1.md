# 交付规则集 v1（口播视频 · 每次必执行）

> 适用：任何「真人出镜口播 → 成片」任务，从开工到交付。
> 原则：**每条规则必须能判真假；判不了的规则不算规则。**
> 冲突裁决顺序（写死，不许临场决定）：
> **内容完整/事实正确 > 不误导 > 用户明确说过的偏好 > 风格节奏 > 时长/字数/体积**

---

## 第一段 · 开工前（5 件事，缺一件不许动手）

**R1 需求六段**（用户没给全，我补全并复述确认）
```
目的 / 成品判据（可数）/ 反例 / 优先级 / 必须跑的自检 / 做不到怎么办
```

**R2 四文件夹轮询**（每次都要，不许凭记忆）
```
① Agent-Motion 会员手册   ② 导演是我 01/02/03（5 文件）
③ Agent-Knowledge-Loop    ④ IP 打造 20 页 + SURGE design.md
```
判据：每份都产出「页码/行号 + 原文摘录」，写不出行号 = 没读。

**R3 条款四归属**（168 条级别的清单，逐条标）
```
已用（指出落在哪段/哪个组件） / 本轮用（进返工清单带判据） /
不适用（写理由：竖屏专用、与原片比例冲突、前期流程已过） / 拿不到（缺件，当场报用户）
```
判据：不许出现「都用上了」这种整体说法；缺件必须单独列出。

**R4 冲突先裁决再动手**
遇到材料与用户口径打架（例：SURGE 2880×2160/4:3 vs 原片 16:9）：
先按第一段优先级判，再**明说哪条不用、为什么**。判据：交付说明里有一行「不采用项 + 理由」。

**R5 先锁时间线，再导 SRT，再动画面**
```
粗剪锁定 → 用户确认「不再改台词顺序和时长」→ 导出/校正 SRT → 才做视觉
```
判据：SRT 时间码单调递增、无重叠、与成片同版；改一次时间线 = SRT 立即作废重导。

## 第二段 · 制作中（视觉硬判据）

**R6 内容跟口播顺序出现，禁止整页一次弹出**
判据：每个元素入场时间 = 对应语义段起点；「整页同时出现」次数 = 0。
> 出处：Agent-Motion:171「根据口播出现的顺序，而不是上来就是一整页全部都出来了」

**R7 元素入场要有先后与停留**
判据：相邻元素入场间隔 ≥0.25s；重点元素停留 ≥1.5s（够读完）。

**R8 不许整片只放字**
判据：纯文字页占比 ≤30%；每 15s 至少 1 个图形/结构/示意。
> 出处：Agent-Motion:191「不是因为你没给图片，就整片只放字」

**R9 框与描边只留一个**
判据：圆窗只有底盘，无描边、无白边、无红框。
> 出处：Agent-Motion:205

**R10 每帧一个焦点，强调色 ≤2 处**
判据：视觉焦点 = 1；橙色/高饱和强调 ≤2 处；陪衬元素 ≤ 主角尺寸/2.5 且错位。

**R11 位移必须缓动，禁止 linear**
判据：所有位移动画用 ease-out / back / elastic；linear = 0；单元素不叠加两段 transform。

**R12 数字不许编**
判据：屏幕出现的每个数字都能在稿子/资料里找到出处；编造 = P0。

**R13 字幕三条线**
```
位置：x=60 起，宽 ≤730，底边距 32±4px，最多 2 行
断行：只断在标点或词边界，单字行 = 0
层级：字幕永远在最上层，人物任何像素不得进入字幕矩形（间距 ≥24px）
```

**R14 抠像三条线**
```
圆窗外 alpha 全 0；孤立前景块 <30px² 清掉；边缘羽化 1.5–2px
抖动：连续 12 帧同像素 alpha 标准差 ≤8（超了就上 P30 时域钳制）
```

## 第三段 · 交付前（6 项质检 + 三件套）

**R15 抽 5 帧实看**（不看缩略图、不看技术指标）
```
字幕读得完 / 人像无缺块 / 页面衔接无跳变 / 大字与人物同时看清 / 无黑块残留
```

**R16 首尾各回听一句**
判据：原话完整、口型与语音偏差 ≤1 帧、无半句起头。
> 这条是为「剪掉开头 5.2 秒」立的：任何为时长做的删减，必须回查前后各一句。

**R17 专有名词零错字**
判据：人名/产品名/品牌名/英文缩写/数字单位逐项核对，错字 = 0。

**R18 公网交付**
判据：`chmod 644` + 逐条 `curl` 得 HTTP 200 + 字节数与本地一致；不凭目录推断。

**R19 四件套齐全才叫交付**
```
主片（mp4）+ 自检输出（PASS/FAIL 表）+ 抽样帧（3–5 张）+ 规格表（参数/判据/不采用项）
```
缺任一件 = 未交付，不许说「已完成」。

## 第四段 · 工作安排（不只管做错，也管没做）

**R20 工单必须有主**
每张 open 工单必须写：负责人 + 下一次动作时间。任一为空 → 立即上报用户，不许沉默。
判据：台账扫描时，open 且无主 = 0 条。

**R21 日报四段固定**
```
1 已完成（带可下地址/数字）
2 进行中（谁在做、做到哪、预计何时）
3 逾期/卡住（卡在哪一步、不是"在办"）
4 需要你定（最多 3 条，每条给选项）
```
判据：不许只报第 1 段。

**R22 说不许含糊**
```
做不到 → 说缺什么、影响哪一步、什么时候补
没测过 → 说没测，不许用"应该没问题"
没安排 → 说没安排，不许用"在推进"
```

---

## 第五段 · 维护

**R23 新教训的落法**
一条教训 → 先改成一条可判定的 CHECK → 再写进本文件对应段落 → 最后进返工脚本。
只写文字不进 CHECK 的教训，下次照样漏（本文件就是为此存在）。

**R24 每轮只改 1–3 个变量**
改完重跑同类画面比对，不许一次改十处导致无法归因。
