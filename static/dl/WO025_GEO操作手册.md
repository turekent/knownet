# GEO 操作手册（个人 / 门店 · 让 AI 搜索找得到你）

> 本手册只写有证据的动作，不写价格、不承诺未验证的效果。结论口径一句话：能卖的是「检索排位 / 证据块 / 爬虫放行 / 实体一致性」，不是 llms.txt 和 FAQ 堆砌。下文「证据①②③④⑤」指文末对应的五项实测证据。

---

## 第一章 · 先测再改

**做法**：开工前冻结 10 个问题，一次定死、中途不改。5 个取自己场景，5 个取模拟客户场景，全部取自「用户真会拿去问 AI 的那句话」，按四类分层——发现型（「XX 是谁」）、比较型（「XX 和 YY 哪个好」）、场景型（「XX 怎么做 / 怎么参与」）、品牌防御型（「XX 靠谱吗」）。问题要带真实限定词：地名、行业、品类，避免被同名污染干扰。每个问题跑一遍目标 AI（豆包 / 元宝 / DeepSeek / 秘塔等），逐条记录三类结果：是否提到品牌全名或固定别名、提到的事实对不对、能否追溯到某一页。连同引擎名、终端（Web / App）、日期一起存成 JSON 基线文件，文件里留「判定标准」字段，保证下次复测用同一把尺子；再给每个问题标一个「期望答案来源」——品牌防御型期望官网、发现型期望百科或身份页，后面复测才知道该去查哪一页。

**为什么**：没有基线，改完无从判断是「变好了」还是「本来就那样」。这是整套方法里最便宜、也最容易被跳过的一步，跳了就变成拿感觉当结论。冻结问题集是为了堵死「测不过就换题」的自证循环——题一改，「7/10 通过」就成了自娱自乐。分层是因为不同问法走不同信源，混在一起算不出有效结论；带真实限定词是因为同名实体太多，不带限定词测出来的是「同名的人」而不是「你」。

**怎么验**：基线要能复现，不是「跑一遍拉倒」。固定引擎、固定问法、固定判定标准，每次复测只报 x/10 与变化原因。第一条纪律：报数前先跑一条「已知答案」的对照查询，确认搜索后端没坏——后端坏掉的症状是「返回结果与查询无关」，此时 0/10 是假数据，绝不能报；结果「主题相关但不含目标实体」才是真实的 0，可以报。第二条纪律：页面刚上线时命中为 0 是正常基线，不是失败，别用「已优化」这类话掩盖它。存档文件名带上日期和实体名，方便按周 diff；变化只报数字和方向，不铺搜索结果清单。

## 第二章 · 让机器认得出你是谁

**做法**：把「名称、身份描述语、联系方式、结构化数据」四样做到跨平台逐字一致。名称用平台真实显示名，不是口述简称——用户常说的简称和平台实际显示名不一致，不一致就会被判成两个实体。身份描述语固定成一句话（如「XX，某领域从业者，主要写某某」），GitHub / 知乎 / 身份页 / 各平台简介一字不改；联系方式（官网 / 邮箱 / 营业地址 / 电话）每处出现格式统一，避免一会儿「XX路1号」一会儿「XX路一号」；结构化数据用 schema.org JSON-LD 的 Person / Organization，写清 name、description、url、sameAs，sameAs 填真实可点的平台链接。同一实体在多个平台的名称、描述语、链接做成一张对照表，放在身份页里，既是台账，也是给机器看的 self 参照。

**为什么**：AI 靠「唯一标识 + 事实源」认实体。名称不一致（简称 vs 全称）会被判成两个实体，前面全白做；身份描述语每处写法不同，AI 拼不成一个实体；sameAs 是 AI 认「同一个人 / 同一家店」的关键信号，光写名字它只能猜。结构化数据的价值在「一致性锚定」，不在数量——它不是「加一段就提升引用」的魔法，别指望靠它换 AI 引用；真正有用的是把事实写进可见正文，让机器读得懂「你是谁、做什么、怎么联系」。

**怎么验**：逐平台核对「账号名 == 实际显示名」；逐一核对描述语是否逐字一致（改一处要台账式改全部，别只改首页）；sameAs 每个链接都能点开且指向对的页，抖音这类要取真实主页 URL 而不是 user/self 短链；全站 grep 确认没有残留的旧名称、旧写法。名称撞上强语义词（如笔名撞健身词）时，处理办法不是改名，而是固定搭配——每次出现都带「名称 + 那句统一身份描述语」，让引擎学会消歧。注意区分：封闭平台的简介是给人看的，不能当优化动作；但公网可抓的知乎简介例外，必须放那句逐字一致的描述语。

## 第三章 · 让内容被检索到

**做法**：把内容做成「机器能检索、能摘抄」的形态。一是页面结构：题意化标题（标题直接是用户会问的那句话）+ 模块化短节（定义 / 对比表 / 步骤 / 数字），不要整段散文，让检索和摘抄都能定位到具体小节；二是可引用段落：每个要回答的问题给一段可直接摘抄的定义句或结论句，五六十字、含实体名，能被原文抄走；三是证据块：统计数字、引语、具名引用，一处一用，写进可见正文，不要藏在 meta 或注释里——AI 只读可见文本，藏在标签里的等于没写。每个页面只回答一个问题，一页一题意；多个问题拆成多页，别挤在一页里稀释信号。

**为什么**：AI 引用 = 检索召回 + 生成摘抄，两步缺一不可。检索排位是所有方法的前提（证据⑤：C-SEO Bench 显示排位提升远大于写作技巧），进不了候选集，内容再好也白搭；进了候选集之后，决定能不能被「抄走」的是段落里有没有定义、数字、对比这类证据块——这是唯一有同行评审数字支撑的改写手法（可见性 +30~40%）。长度本身不是充分条件，灌水长文无效，模块化短节才有效；「看起来更友好」的改写在大规模对比里失效甚至负向。题意化标题是为了让召回直接命中：标题不带用户的原问法，召回就落空，证据块再好也进不了上下文。对比表和步骤是最容易被 AI 原文搬用的体裁，定义句次之；数字要写清口径和出处，没出处的数字 AI 不敢用。

**怎么验**：对每个冻结问题，看目标页面是否被检索召回（搜索引擎前几页）；抓取页面正文，确认定义句、数字、对比块确实在可见文本里且含实体名；用「这段能不能被直接原文引用」的标准自测——能被抄走才算，泛泛的「看起来专业」不算。每篇内容改完顺带产出一份「文字块」清单，把可引用句单独列出来，既是原料也是验收单。标题要和冻结问题里的原句对得上，对不上的先改标题再谈内容。复核时数一下页面里定义 / 对比 / 步骤 / 数字各出现几次，四类都有才算结构达标，缺一类回去补。

## 第四章 · 分发与外部提及

**做法**：三件事按优先级做。第一，放行检索类爬虫（OAI-SearchBot / ChatGPT-User / Claude-SearchBot / PerplexityBot），挡训练类爬虫（GPTBot / ClaudeBot / Google-Extended）不影响被引用，别混在一起；第二，补可发现性：robots.txt 放行 + sitemap.xml + IndexNow 主动推送 + 外部链接——爬虫靠链接发现新域名，没人链过来可能永远不收录，这是最容易漏的一步；第三，外部提及：把可核验事实同步到百科 / 权威媒体 / 高质量社区的一致表述，官网保留可摘抄定义块。一条带职务署名的第三方提及，权重高于自己发一百条，是最该先做的一条。外部提及优先挖「带名字的」：论文署名、活动通稿、获奖名单——项目报道一大把但没带名字，对 AI 等于零。

**为什么**：挡住训练爬虫不等于从答案消失——证据④实测挡掉 GPTBot 的新闻站仍有 88% 被 ChatGPT 引用，因为答案可经第三方检索旁路进入。所以要分爬虫类型，检索 / 用户拉取类必须放行，训练类挡了也没用。AI 高频被引的域以百科、社区、通讯社为主，第三方一致表述是慢功夫但权重最高；官网在「定义 / 规格」类问题里仍不可替代，别把官网内容全删光去追第三方。外部提及不是「买通」：第三方高引不等于可买，要的是可核验事实的一致表述，不是付费软文。

**怎么验**：体检爬虫可达性——检查 robots.txt、CDN / WAF 是否对检索类爬虫返 403；用爬虫模拟器抓目标页确认可读；数外部提及的「可抓链接条数」当进度指标，条数涨才是真进展；发布后当天到微信生态内（元宝 / 搜一搜）验一次，别照搬外部搜索引擎「1–6 周收录」的常识——微信生态内是天级。同一事实在多个第三方来源里的表述要一致，表述打架比没有更糟。

## 第五章 · 复测与判定

**做法**：用第一章冻结的同一套 10 个问题每周跑一次，只报 x/10 与变化。判定「通过」三条全中：品牌被提到（全名或固定别名）、提到的事实正确、能追溯到我们改过的那一页（不是碰巧撞上）。多轮取样（≥3 轮）再下结论，报提及率 + 置信区间，单轮不下结论；「被选中」与「被吸收」分开记——进引用列表和进答案表述是两个不同指标，可以不同步，要拆开看。每次复测固定同一时间跑，结果记成表格：日期、引擎、x/10、较上周变化、哪个问题动了、动了是升还是降。两类数字都记：被选中次数（进了引用列表）和被吸收次数（进了答案表述），别只记一个总分。

**为什么**：单轮结果不稳定，一次命中可能是随机；追溯到改过的那一页才能排除「本来就能搜到」。分开两个指标是为了看清卡在哪一层——被选中但没被吸收，说明证据块不够；没被选中，说明检索排位没解决。改完不等于立竿见影：搜索缓存滞后几天，页面改了别以为没生效就反复重改，先确认源头写入成功再等缓存。改完也不是一劳永逸——检索排名会随竞争对手动作、索引更新而浮动，所以复测是持续监测不是一次性验收，掉下来要回去查是哪一层被挤了。被吸收才是客户真正要的——AI 在答案里说出事实，比只是列个链接有价值得多，所以两个指标必须分开，混成一个分会把「被选中」误当成成功。

**怎么验**：≥7/10 才算「可对外」，5–6 只内部用，≤4 回到验证。诊断可以 0 成就卖（卖的是测量，报告陈述事实）；修复必须过 7 成（卖的是改变结果，没测过就是拿客户钱做实验）。最后让用户自己在真实豆包 / 元宝里问一遍做交叉验证，别只信自测的代理数字；中文场景要分 Web / App 终端，不同终端信源生态不同，不能混算成一个分。连续四周 ≥7/10 才算稳定通过，单周冲高不算数；要报「稳定通过」而不是「某一次通过」。复测结果回写进同一个基线文件，形成时间序列；报变化时带上上一次的数字，让人看得出趋势而不是孤点。

## 不要做清单（每条对应文首的证据编号）

1. **不要卖「llms.txt 提升 AI 排名」**——Google 官方明确不使用 llms.txt、不影响可见性；规范只承诺降低取数成本，从不承诺引用率。证据①
2. **不要挂个 llms.txt 就宣称「已对 AI 优化」**——13.7 万站样本里 97% 的 llms.txt 当月零请求，等于挂在那儿没人读。证据②
3. **不要把 llms.txt 写进 KPI 或验收项**——它做与不做都不改变引用结果，拿它当指标等于考核一个无关变量。证据①②
4. **不要堆 FAQ 当被引卖点**——480 次查询实测，带 FAQ 的页面引用率 6.7%，反而不带的 8.3%，FAQ 壳反而更低。证据③
5. **不要只加 FAQPage JSON-LD 空壳**——价值在答案内容里有没有定义 / 数字 / 对比，不在问答格式；空问答等于白做。证据③
6. **不要把 FAQ 富结果当引流**——搜索引擎侧的 FAQ 富结果已下线，这条路已经断了。证据③
7. **不要把「挡 GPTBot」当防御或隐私手段卖**——挡掉 GPTBot 的新闻站仍有 88% 被 ChatGPT 引用，答案经第三方旁路照样进。证据④
8. **不要一刀切挡所有 AI 爬虫**——训练类爬虫挡了不影响被引用，检索 / 用户拉取类爬虫必须放行；挡错类型等于自己退出 AI 检索。证据④
9. **不要只做「AI 文风改写」不碰检索排位**——检索排名提升远大于写作技巧，进不了候选集，改写收益全被抵消。证据⑤
10. **不要灌水加长凑「内容深度」**——长度不是充分条件，大规模对比里「看起来更友好」的改写失效甚至负向。证据⑤
11. **不要卖泛化 JSON-LD（加段 Article / Organization 换引用）**——官方明说进 AI 功能不需额外 schema，主导因素是排位不是标注。证据⑤
12. **不要承诺「保证被 AI 引用 / 指定排名 / 指定输出」**——训练数据不可控，联网检索可测但无人能保证，任何保证话术都无证据支撑。证据①⑤
