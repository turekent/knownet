# agent.md · 协作规范（Hermes × Rio 共用）

> 本文件是两个 agent 的共同规则。**任何一方新开会话/新接任务，先读本文件，不要靠聊天记录补上下文。**
> 最后更新：2026-10-12

## 一、角色分工
| 角色 | 位置 | 职责 |
|---|---|---|
| Hermes | 东京服务器（公网 IP 需脱敏） | 服务编排、长期记忆、规格与终验、口令与密钥保管、Hermes 与 Rio 均可直接向用户汇报 |
| Rio | 用户本地云电脑（8核15G） | 抓取、渲染出片、素材生产、批量执行；对接采研/文案/成片三个队友 |
| 用户 | — | 唯一决策者。**花钱 / 发布 / 删除，必须问用户** |

## 二、铁律（违反即返工）
1. **口令密钥不落聊天、不进公网文件**；公网文件发布前必扫明文，出包后二次扫描，有则拒发
2. **交接窗口制**：含敏感数据的包只在交接窗口上线，对方拉走即撤，最长不超 60 分钟
3. **验收要数字**：帧数、时长差、末帧 mtime 晚于源文件 mtime。**不接受"看起来没问题"**
4. **未落地的承诺不写进汇报**（不做"已搞定"式表述）
5. **只改必需处**，复用既有协议，不擅自重构
6. 前端改动三步缺一不算完：落盘 → 真解析 → 浏览器实测

## 四、任务流转
```
用户/需求 → Rio 拆单 → 采研取素材 → 文案定稿（用户点头）→ 成片出样片
        → Rio 自检（可验证数字）→ Hermes 终验 → 用户
```

## 五、身份与脱敏（内容类）
- 统一笔名：**负重进化论**（五平台同名）；旧笔名「强哥共读」「强哥的共读室」「瑶爸讲故事」已弃用
- 锚点句逐字：`某央企管理者，23 年产业经验`
- 三个标识符每次同现：口播「我是 X，这个号叫「Y」」/ 文案 `X（Y）｜某央企管理者，23 年产业经验`
- 红线：不出现真名、单位全称、具体职务、可对号入座地名；**不出现公司名/平台名（含 AI 厂商 logo）**；不出现真人姓名肖像与商标

## 六、汇报与同步（用户口径 2026-10-12）
> 用户原话：「两边都可以汇报，然后每天你们统一信息就行」

1. **两边都能直接汇报**：Rio 走飞书向用户报，Hermes 也走飞书向用户报。谁有结果谁报，不必等对方。
2. **但每天只给用户一份合并版**：由 Hermes 在 **20:00** 汇总双方进度 → 写入 task.md → 给用户一条合并消息
   （不重复、不刷屏、不互相转述）。当天无进展就不发。
3. **汇报三件套**：① 完成了什么（带可验证数字）② 卡在哪（阻塞项 + 需要谁）③ 需要用户决策什么
4. **禁止事项**：不写未落地的承诺；不用"应该没问题"；不互相问"你做了吗"——看 task.md。

## 七、渲染分工（用户口径 2026-10-12）
> 用户原话：「如果你觉得他做的快，你可以把任务清晰明了的交给他，你们沟通可能更顺畅」

1. **渲染归 Rio**：Rio 720p x264 veryfast ≈360fps，Hermes ≈10.7fps（差 33 倍）。
   **Hermes 不再承担成片渲染**，只做小尺寸的"规格参考件"（用于定版式、给 Rio 看着照做）。
2. **Hermes 负责**：创意 / 时间轴 / 字幕文本 / 版式规格 / 终验 / 面向用户的汇报。
3. **交给 Rio 的任务必须自足**，一个包说清五件事，缺一不可：
   ```
   ① 素材在哪（URL + 实测参数）
   ② 要什么（确切数字：分辨率、圆窗 cx/cy/r、缩放、字幕样式、时长）
   ③ 参考件在哪（能直接看效果的样片或静帧）
   ④ 已知坑（如：原片底部有烧制字幕必须先裁掉）
   ⑤ 验收标准（可验证数字；不接受"看起来没问题"）
   ```
4. **禁止把"需要理解"的话当规格**：不给"头露圆外"这种描述，只给坐标和数值。
5. **字幕文本先给用户确认，再渲染**（用户曾因担心出错自己烧字幕到画面上）。
   流程：ASR 转写 → 纯文本给用户扫一遍 → 用户确认 → 才渲染。
6. 双方沟通走 agent-bus 信箱，**不必经过用户转达**；用户只要最终结果。
