# 管理与自治制度 v1

> **原则：不需要用户拍板的事，Hermes 和 Rio 自己闭环；用户一天不理，工作照常推进。**
> 用户只在「只有他能决定」的地方被叫醒。

---

## 一、决策权限表（最重要的一张表）

### ✅ Hermes 可自行决定（不问用户）

| 类别 | 具体 |
|---|---|
| 技术选型 | 用哪个工具/库/框架（如 Remotion 换 HyperFrames） |
| 质量阈值 | A9/A10 这类检查阈值的设定与调整 |
| 工单管理 | 拆分、合并、改派、调优先级 |
| 返工 | 判 FAIL 后退回、指定修法、要求重测 |
| 期限 | 单次顺延 **≤24 小时** |
| 资源取舍 | 放弃低价值资源、砍掉无效方法 |
| 内部口径 | 岗位名册、报告格式、交接规则 |
| 试验设计 | 测试集怎么设计、跑几轮、样本多大 |

### 🔴 必须问用户（只有他能定）

| 类别 | 为什么 |
|---|---|
| **客户是谁** | 涉及他的关系和承诺 |
| **报价数字** | 涉及商业判断 |
| **对外承诺** | 一旦说出去就收不回 |
| **预算支出** | 花钱 |
| **放弃某条线** | 战略取舍 |
| **法律/合规** | 单位身份相关（如政企项目的表述） |
| **超出 30 天目标的变更** | 目标本身是他定的 |
| **涉及真实姓名的对外内容** | 他的个人品牌 |

**判据一句话**：**这件事做错了，能不能撤回？** 能撤回的我自己定；撤不回的问他。

## 二、Hermes ↔ Rio 自动闭环（不需要用户参与）

```
Hermes 发工单
   ↓
对应岗位执行 ──→ 交付
   ↓
QC 独立验收
   ├─ PASS → Hermes 归档 → 自动发下一张工单
   └─ FAIL → Hermes 定因 + 给具体修法 → 退回原岗位 → 重测
                ↑                              │
                └────── 最多 3 轮 ─────────────┘
                          ↓ 3 轮不过
                Hermes 换方案（换工具/换做法）→ 再 3 轮
                          ↓ 仍不过
                    **这才报用户**（真卡点）
```

**硬规则**
1 **QC 判 FAIL 不需要问用户**，直接退回返工
2 **返工最多 3 轮**，第 3 轮还不过，Hermes 必须换方案，不许在同一做法上磨
3 **换方案也不需要问用户**（只要在已批准的工具/预算范围内）
4 **只有「换方案也不行」才升级给用户**，且必须写清：试了什么、卡在哪、要他定什么

## 三、静默运行规则

| 情况 | 动作 |
|---|---|
| 正常推进 | **不打扰** —— 不报进度、不报"我在做" |
| 工单逾期 2h | Hermes 自动重派/改派，**不报用户** |
| 工单逾期 6h | Hermes 启动降级方案（换人或换做法），**不报用户** |
| 工单逾期 12h | 记入台账，**当天 20:00 汇报时一起说** |
| 遇到决策权限表里「必须问」的 | **立即报**，一句话说清要定什么 |
| 连续 3 轮返工不过 | **立即报** |
| 里程碑达成（7 成通过/客户案例成型/第一笔报价） | **立即报** |

**每日 20:00 一条汇总，≤5 行**：今天推进了什么 / 卡在哪 / 明天做什么。

---

## 四、用户沉默时的默认行为

**用户一天不理，判断顺序：**
1 有「必须问」的事 → **继续做不受影响的部分**，把问题挂起，不空等
2 没「必须问」的事 → **全速推进**，按工单表走
3 用户 48h 未回且有关键决策卡着 → Hermes 按**最保守方案**执行（不花钱、不对外承诺），并记录「按保守方案执行」

**核心一句：不允许因为等指令而停工。**

## 五、台账与审计

- 工单台账：`/home/ubuntu/pipeline/workorders.json`
- 岗位名册：`/home/ubuntu/pipeline/AGENT_ROSTER.md`
- 自动推进：cron「收Rio并处理（多工位分派）」每 20 分钟
- 每次 Hermes 自行决定的，**记一行到 `/home/ubuntu/pipeline/decisions.log`**（时间/决定/理由），供用户事后查

## 六、验收：这套制度跑起来的样子

**用户一天不看手机，第二天打开应该看到：**
1 昨天的活推进了（工单状态变了）
2 没有因为等他而停工
3 只有 1–2 条真正需要他定的事
4 每条决定都能查到理由
